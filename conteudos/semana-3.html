Controle de versão

Por que usar Git

Git registra versões do projeto. Cada commit funciona como um ponto identificado no histórico e permite acompanhar o que mudou ao longo do desenvolvimento.

Repositório

Pasta acompanhada pelo Git.

Commit

Registro de um conjunto coerente de alterações.

Branch

Linha de desenvolvimento do projeto.

Remote

Referência para uma cópia hospedada, como o GitHub.

git init
git status
git add .
git commit -m "Cria estrutura inicial"

Repositório remoto

Publicação no GitHub

Git e GitHub não são a mesma coisa. Git é a ferramenta de versionamento; GitHub é um serviço que hospeda repositórios e facilita colaboração e apresentação do código.

git branch -M main
git remote add origin URL_DO_REPOSITORIO
git push -u origin main

Mensagens de commit devem explicar a mudança realizada, por exemplo: Adiciona página de contato ou Corrige validação do formulário.

Back-end

Primeiro contato com PHP

PHP é executado no servidor. O navegador recebe somente o resultado gerado. No ambiente local, o XAMPP fornece o servidor Apache e os recursos necessários.

<?php
$curso = 'Desenvolvimento Web Full Stack';
$cargaHoraria = 40;
?>

<h1><?= htmlspecialchars($curso) ?></h1>
<p>Carga horária: <?= $cargaHoraria ?> horas.</p>
Atenção: arquivos PHP precisam ser acessados por um servidor, como http://localhost/projeto. Abrir o arquivo diretamente não executa o código.

Do código ao navegador

Entenda o fluxo de trabalho

O Git acompanha os arquivos no computador, enquanto o GitHub recebe uma cópia do histórico por meio do push. Já o servidor local executa o PHP e devolve HTML ao navegador. São ferramentas diferentes, usadas em etapas complementares.

  1. git status mostra arquivos novos ou modificados.
  2. git add seleciona as mudanças que entrarão no próximo registro.
  3. git commit cria um ponto no histórico local.
  4. git push envia commits para o repositório remoto.
  5. Apache recebe uma requisição, executa o PHP e entrega o resultado ao navegador.

PHP no servidor

O trecho entre <?php e ?> é processado antes de a resposta sair do servidor. Variáveis PHP não aparecem no código-fonte recebido pelo navegador; apenas o texto ou HTML produzido por elas é enviado.

Revise: saiba diferenciar Git de GitHub, explicar as etapas status, add, commit e push, e justificar por que um arquivo PHP precisa de servidor.

Prática sugerida

Versione e execute o projeto

  1. Inicie um repositório na pasta do projeto.
  2. Registre a versão atual em um commit.
  3. Crie um repositório remoto e envie a branch principal.
  4. Prepare uma pasta no XAMPP e crie um index.php.
  5. Mostre pelo PHP o nome e a carga horária do curso.
