Controle de versão

Por que utilizar Git

Durante o desenvolvimento, os arquivos mudam muitas vezes. O Git é uma ferramenta de controle de versão: ele registra essas mudanças, organiza o histórico e permite identificar quando e por que cada alteração foi realizada.

O Git trabalha no computador. Ele não precisa do GitHub para criar um repositório ou registrar commits. Depois, se desejar, você pode conectar o histórico local a um serviço remoto.

Repositório

Pasta acompanhada pelo Git, com arquivos e histórico de alterações.

Commit

Registro de um conjunto coerente de mudanças em determinado momento.

Branch

Linha de desenvolvimento que organiza uma sequência de commits.

Remote

Referência para uma cópia remota do repositório, como a hospedada no GitHub.

Uma comparação útil: salvar um arquivo atualiza seu conteúdo no computador. Criar um commit registra uma versão identificada no histórico do Git.

Fluxo local

Do repositório ao primeiro commit

Os quatro comandos abaixo formam um fluxo básico. Eles possuem funções diferentes e devem ser lidos como etapas: iniciar o acompanhamento, observar mudanças, selecionar arquivos e registrar uma versão.

1. Iniciar o repositório

git init cria a estrutura interna utilizada pelo Git na pasta atual. Normalmente, esse comando é necessário apenas uma vez em cada repositório.

git init

2. Consultar a situação dos arquivos

git status informa quais arquivos são novos, quais foram modificados e quais já estão preparados para o próximo commit. Ele apenas consulta o estado: não registra nem envia arquivos.

git status

3. Selecionar as alterações

git add coloca as mudanças na área de preparação. Essa etapa define o que fará parte do próximo registro.

git add index.php

# O ponto seleciona todas as mudanças da pasta:
git add .

4. Registrar uma versão

git commit cria um ponto no histórico local com as alterações preparadas. A mensagem deve resumir o que foi feito de forma clara.

git commit -m "Cria primeira página PHP"

status

Mostra a situação atual dos arquivos.

add

Seleciona mudanças para o próximo commit.

commit

Registra uma versão no histórico local.

Repositório remoto

Git e GitHub não são a mesma coisa

Git é a ferramenta que controla versões. GitHub é uma plataforma on-line que hospeda repositórios Git e facilita compartilhamento, colaboração e apresentação do código.

Depois de criar um repositório no GitHub, o endereço dele pode ser associado ao repositório local. Por convenção, essa referência costuma receber o nome origin.

git branch -M main
git remote add origin URL_DO_REPOSITORIO
git push -u origin main

git push envia para o repositório remoto os commits que já existem localmente. Ele não substitui git add nem git commit: primeiro as mudanças são registradas no computador e depois os commits são enviados.

Histórico local

É criado e consultado pelo Git no computador.

Cópia remota

Fica hospedada em um serviço como o GitHub.

origin

Nome convencional dado ao endereço remoto principal.

push

Envia commits locais para o repositório remoto.

Primeiro contato com o back-end

PHP é processado no servidor

HTML, CSS e JavaScript são interpretados pelo navegador. O PHP segue outro caminho: seu código é executado no servidor antes de a resposta chegar ao navegador. A pessoa usuária recebe somente o resultado produzido, geralmente em HTML.

Delimitadores e instruções

Um bloco PHP começa com <?php. Quando o arquivo também possui HTML, o bloco pode ser encerrado com ?>. As instruções normalmente terminam com ponto e vírgula.

<?php
// Este é um comentário de uma linha.
echo 'Minha primeira mensagem em PHP';
?>

echo envia um texto ou valor para a resposta que será entregue ao navegador. O comentário explica o código e não aparece na página.

Variáveis e tipos de valores

Em PHP, os nomes das variáveis começam com $. Não é necessário declarar o tipo antes do nome: o PHP reconhece o tipo a partir do valor atribuído.

<?php
$nome = 'Ana';                    // string
$semana = 3;                      // integer
$cargaHoraria = 40.0;             // float
$conteudoDisponivel = true;       // boolean
$tecnologias = ['Git', 'PHP'];    // array
?>
String

Texto escrito entre aspas, como 'PHP'.

Integer e float

Números inteiros ou com casas decimais.

Boolean

Valor lógico representado por true ou false.

Array

Estrutura que reúne vários valores em uma coleção.

Concatenação e interpolação

O operador ponto (.) une textos e valores. Em uma string com aspas duplas, uma variável simples também pode ser inserida diretamente no texto.

<?php
$nome = 'Ana';
$semana = 3;

echo 'Olá, ' . $nome . '!';
echo "Você está na semana $semana.";
?>

PHP junto com HTML

Um arquivo .php pode alternar entre blocos PHP e marcação HTML. A forma abreviada <?= ... ?> exibe o resultado de uma expressão dentro do HTML.

<?php
$curso = 'Desenvolvimento Web Full Stack';
$cargaHoraria = 40;
?>

<h1><?= htmlspecialchars($curso) ?></h1>
<p>Carga horária: <?= $cargaHoraria ?> horas.</p>

htmlspecialchars() converte caracteres especiais antes de mostrar um texto no HTML. Esse cuidado se torna especialmente importante quando o valor vier de uma pessoa usuária ou de outra fonte externa.

O papel do XAMPP e do Apache

O XAMPP reúne ferramentas para criar um ambiente de desenvolvimento local. Entre elas está o Apache, que recebe a requisição do navegador, executa o arquivo PHP e devolve a resposta gerada.

  1. O arquivo index.php fica dentro de uma pasta servida pelo Apache, como htdocs.
  2. O navegador solicita uma URL, por exemplo http://localhost/minha-pagina/.
  3. O Apache encontra o arquivo e encaminha o código PHP para processamento.
  4. O resultado em HTML é devolvido ao navegador.
Atenção: abrir um arquivo PHP diretamente pelo explorador de arquivos não executa seu código. É necessário acessá-lo por um servidor configurado.

O que chega ao navegador

Variáveis como $curso e instruções entre <?php e ?> permanecem no servidor. No exemplo, o navegador recebe o título e o parágrafo já preenchidos, não as instruções PHP originais.

Erros iniciais comuns

  • Abrir o arquivo diretamente em vez de usar um endereço com localhost.
  • Salvar o arquivo fora da pasta atendida pelo Apache.
  • Esquecer o ponto e vírgula no final de uma instrução.
  • Acessar a página com o Apache desligado no painel do XAMPP.
  • Usar uma variável com grafia diferente, pois $curso e $Curso são nomes distintos.

Prática sugerida

Crie, versione e execute uma página PHP

  1. Crie uma pasta chamada pratica-semana-3 dentro de htdocs.
  2. Adicione um index.php com variáveis para título, nome e número da semana.
  3. Mostre os valores com echo, concatenação e a forma abreviada <?= ... ?>.
  4. Acesse a página pelo endereço http://localhost/pratica-semana-3/.
  5. Inicie um repositório e consulte o estado dos arquivos.
  6. Prepare o arquivo e crie um commit com uma mensagem clara.
  7. Como etapa opcional, publique o repositório no GitHub.

Critérios para conferir sua prática

A página deve ser processada pelo Apache, exibir corretamente os valores definidos no PHP, misturar PHP e HTML sem erros e possuir pelo menos um commit no histórico local.
