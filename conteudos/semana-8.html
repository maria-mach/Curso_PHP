Integração

O que é uma API REST

Uma API permite que aplicações troquem informações. Em uma API REST, recursos são representados por endereços chamados endpoints e manipulados por métodos HTTP.

GET    /api/tecnologias
GET    /api/tecnologias/10
POST   /api/tecnologias
PUT    /api/tecnologias/10
DELETE /api/tecnologias/10

Comunicação

Métodos e respostas HTTP

GET

Consulta um recurso sem alterá-lo.

POST

Cria um novo recurso.

PUT

Atualiza um recurso existente.

DELETE

Remove um recurso autorizado.

As respostas também possuem códigos de estado: 200 para sucesso, 201 para criação, 400 para requisição inválida, 404 para recurso ausente e 500 para falha interna.

Formato dos dados

Trabalhando com JSON

JSON representa objetos e listas em texto estruturado. PHP pode gerar uma resposta JSON para outras aplicações.

<?php
header('Content-Type: application/json; charset=utf-8');

$dados = [
    'curso' => 'Desenvolvimento Web Full Stack',
    'carga_horaria' => 40,
    'semanas' => 8
];

echo json_encode($dados, JSON_UNESCAPED_UNICODE);

No cliente, a resposta pode ser consultada com fetch() e analisada como JSON.

fetch('/api/curso.php')
    .then(resposta => resposta.json())
    .then(dados => console.log(dados))
    .catch(erro => console.error(erro));

Contrato da API

Uma resposta previsível

Uma API deve combinar conteúdo, código HTTP e cabeçalho adequados. O código informa o resultado geral; o JSON transporta os dados ou uma mensagem que o cliente consegue interpretar.

<?php
header('Content-Type: application/json; charset=utf-8');
http_response_code(201);

echo json_encode([
    'sucesso' => true,
    'mensagem' => 'Tecnologia cadastrada',
    'id' => 12
]);

Um endpoint identifica um recurso, não uma ação visual. Por isso, endereços como /api/projetos são combinados aos métodos HTTP. Antes de devolver dados, a API deve validar a entrada, verificar autorização, tratar falhas e evitar expor detalhes internos do servidor.

Consumo pelo front-end

fetch() inicia a requisição e retorna uma promessa. A resposta deve ser conferida antes de usar os dados. Depois de converter o JSON, a interface pode atualizar seu conteúdo por meio do DOM ou apresentar uma mensagem de erro.

fetch('/api/tecnologias')
    .then(resposta => {
        if (!resposta.ok) {
            throw new Error('Não foi possível carregar os dados');
        }
        return resposta.json();
    })
    .then(dados => console.log(dados))
    .catch(erro => console.error(erro.message));
Revise: relacione recursos, endpoints, métodos e códigos HTTP; reconheça a estrutura do JSON; e explique como front-end, API, PHP e banco participam do mesmo fluxo.

Entrega final

Integração do projeto

A versão final deve demonstrar a conexão entre as partes estudadas:

  1. Interface estruturada com HTML e estilizada com CSS.
  2. Lógica organizada em JavaScript e PHP.
  3. Dados persistidos em MySQL por consultas preparadas.
  4. CRUD completo e formulários validados.
  5. Autenticação com hash de senha e controle de acesso.
  6. Um endpoint criado ou consumido pela aplicação.
Antes da entrega: teste os principais caminhos, trate erros, remova credenciais do repositório e confira a aplicação em telas diferentes.
