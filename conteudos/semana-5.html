GET, POST, validação, sessões e MySQL

Compreenda como dados chegam ao servidor, permanecem entre páginas e são organizados em um banco relacional.

Nesta páginaGET e POSTValidaçãoSessõesMySQLRelaçõesPrática

Requisições

Diferença entre GET e POST

GET

Envia parâmetros pela URL. É adequado para buscas, filtros e páginas que podem ser compartilhadas.

POST

Envia dados no corpo da requisição. É utilizado em cadastros e alterações.

<?php
$busca = trim($_GET['busca'] ?? '');
$nome = trim($_POST['nome'] ?? '');

O método não substitui segurança. Tanto dados de GET quanto de POST devem ser validados no servidor.

Qualidade dos dados

Validar antes de utilizar

Validar significa conferir se um valor está presente, possui formato permitido e atende às regras da aplicação.

<?php
$usuario = strtolower(trim($_POST['usuario'] ?? ''));

if (!preg_match('/^[a-z0-9._-]{3,30}$/', $usuario)) {
    exit('Usuário inválido.');
}
Regra importante: validações do navegador ajudam a pessoa usuária, mas somente a validação no servidor protege a aplicação.

Estado da aplicação

Sessões

HTTP não mantém memória entre páginas. Sessões permitem associar dados temporários a uma navegação, como a identificação de um usuário autenticado.

<?php
session_start();

$_SESSION['usuario'] = [
    'id' => 10,
    'nome' => 'Ana'
];

echo $_SESSION['usuario']['nome'];

Para encerrar, remova os dados da sessão e destrua a sessão quando necessário.

Persistência

Banco de dados relacional

MySQL organiza dados em tabelas. Cada tabela possui colunas, registros e uma chave primária que identifica cada linha.

CREATE TABLE tecnologias (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    categoria VARCHAR(40) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO tecnologias (nome, categoria)
VALUES ('PHP', 'Back-end');

SELECT * FROM tecnologias ORDER BY nome;

As operações principais são INSERT, SELECT, UPDATE e DELETE.

Organização dos dados

Chaves e relacionamentos

A chave primária identifica cada registro sem depender de valores que podem se repetir. Quando uma tabela precisa apontar para outra, utiliza uma chave estrangeira. Assim, um projeto pode pertencer a uma categoria sem repetir todos os dados da categoria em cada linha.

CREATE TABLE projetos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(120) NOT NULL,
    categoria_id INT NOT NULL,
    FOREIGN KEY (categoria_id) REFERENCES categorias(id)
);

Antes de criar tabelas, determine o tipo de cada dado, quais campos são obrigatórios e quais relações existem. Use VARCHAR para textos curtos, TEXT para descrições maiores e INT para inteiros.

Sessão não é banco de dados

A sessão guarda temporariamente informações ligadas à navegação, como o identificador de quem entrou. O banco mantém registros que precisam continuar existindo depois que a sessão ou o navegador forem encerrados.

Prática sugerida

Modele os dados do projeto

  1. Identifique quais informações precisam permanecer salvas.
  2. Crie uma tabela com chave primária e campos obrigatórios.
  3. Insira alguns registros pelo phpMyAdmin.
  4. Execute consultas de seleção, atualização e exclusão.
  5. Registre o script de criação em um arquivo SQL.
